# tg-orders-bot

Telegram-бот приёма заявок на aiogram 3: форма в несколько шагов, хранение в
SQLite, уведомления администратору, админ-панель со сменой статуса и выгрузкой
в CSV, который сразу открывается в Excel.

Готов к продакшену как есть: один процесс, один файл базы, Docker Compose.

## Что умеет

- **Заявка в 5 шагов** — имя, услуга (кнопки), описание, телефон, подтверждение
- **Проверка ввода** — имя 2–80 символов, описание 10–1200, телефон 10–15 цифр,
  `8XXXXXXXXXX` приводится к `+7XXXXXXXXXX`; можно отправить контакт кнопкой
- **Антифлуд** — не больше N заявок за окно (по умолчанию 3 в час)
- **Уведомление админу** — карточка заявки с кнопками «В работу», «Готово», «Отклонить»
- **Обратная связь клиенту** — при смене статуса бот пишет автору заявки
- **`/admin`** — сводка по статусам, последние 10 заявок, выгрузка CSV
- **CSV для Excel** — UTF-8 с BOM, `;`, CRLF: кириллица не ломается
- **«Мои заявки»** — клиент видит свои обращения и их статусы
- **Отказоустойчивость** — ошибки Telegram логируются и не рушат сценарий

## Быстрый старт

```bash
uv sync
cp .env.example .env
# вписать BOT_TOKEN и ADMIN_IDS
uv run python main.py
```

Без uv:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install "aiogram>=3.13,<4"
python main.py
```

Свой Telegram ID можно узнать у `@userinfobot`. Несколько админов — через запятую:
`ADMIN_IDS=111,222`.

## Docker

```bash
cp .env.example .env
docker compose up -d --build
docker compose logs -f
```

База лежит в `./data/orders.db`, она переживает пересоздание контейнера.

## Переменные окружения

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `BOT_TOKEN` | — | Токен от `@BotFather`, обязателен |
| `ADMIN_IDS` | — | ID админов через запятую, обязателен |
| `DB_PATH` | `data/orders.db` | Файл SQLite |
| `CONTACT_USERNAME` | `manager` | Username для кнопки «Связаться» |
| `THROTTLE_LIMIT` | `3` | Сколько заявок можно отправить за окно |
| `THROTTLE_WINDOW_SECONDS` | `3600` | Размер окна антифлуда |

`.env` в `.gitignore`: токен в репозиторий не попадает.

## Структура

```
main.py                 запуск: конфиг, БД, роутеры, polling
app/config.py           чтение окружения и .env, парсинг ADMIN_IDS
app/db.py               SQLite: заявки, статусы, счётчики, CSV
app/keyboards.py        меню, услуги, подтверждение, кнопки админа
app/states.py           FSM-состояния формы
app/texts.py            тексты и валидация ввода (тестируется отдельно)
app/notify.py           безопасная отправка сообщений
app/handlers/user.py    пользовательский сценарий
app/handlers/admin.py   админ-панель
tests/                  pytest: БД, CSV, валидация
```

## Тесты

```bash
uv run pytest
```

Покрыто: создание и чтение заявки, отсутствующая заявка, смена статуса,
счётчики и списки, окно антифлуда, CSV с BOM и разделителем `;`, нормализация
имени, телефона и описания.

## Что заказчику обычно продаётся сверху

- интеграция с Google Sheets вместо CSV;
- оплата (Telegram Payments / ЮKassa) внутри заявки;
- несколько услуг с разными ценами и расчётом стоимости;
- уведомления в отдельный групповой чат вместо личных сообщений;
- хранение в PostgreSQL, если заявок больше десятков тысяч.

## Ограничения

- один процесс: FSM-состояния в памяти, при рестарте незавершённая форма
  начинается заново (данные уже отправленных заявок не теряются)
- нет вебхука: используется long polling, поэтому исходящий доступ в интернет
  обязателен
- нет ролей кроме «админ / не админ»
